# kittyengine

**A code-only, asset-free release of the C++ 2D platformer engine that powers
Raptisoft's *Robot Wants* games** — the engine, its build, a generated
placeholder art pack, four demo levels, and CI that proves the levels are still
completable. There are several unrelated projects called "KittyEngine" on
GitHub; this is not one of them.

It ships **no original art, music, fonts or level data**. Everything you see
when you run it is generated by a script in this repository and dedicated to
the public domain. If you own the original game you can point the engine at
your own copy of its data and get the real thing back — see
[Playing with your own assets](#playing-with-your-own-assets).

Read [LICENSE](LICENSE) before you do anything else: the engine code is
Raptisoft's, its author has agreed in writing to a Creative Commons licence but
has not yet named which one, and this repository is published on that basis
with a standing takedown promise.

## Provenance

This is a fresh history, not a fork. The tree here is the community source
mirror at `31e8e17` plus our own work, with every original asset removed before
the first commit:

| SHA | what it added |
|-----|---------------|
| `31e8e17` | `github.com/rwkcommunity/rwkgame` — the source as its author released it |
| `d379610` | audio backend replacement: BASS gone, one `Sound_Core` on SDL2 + stb_vorbis |
| `4694ced` | the browser renderer: the Linux GL path behind `__EMSCRIPTEN__` guards, drawing through gl11 |

The full lineage stays in a private tree, because the mirror's git history
tracks 998 original asset files and a fork would ship every one of them
regardless of which commit it pointed at.

## Building

### Linux (native, and the headless mode CI uses)

```bash
sudo apt install cmake clang libsdl2-dev libsdl2-image-dev libglew-dev libcurl4-openssl-dev
cd RWK_Source/Games/RWK/Project/Linux
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

The binary lands in `RWK_Source/Games/RWK/Resources/kittyengine`, beside the
assets it loads — the engine's package folder is its own folder.

Run it headless, replaying an input tape and writing one row per tick:

```bash
cd RWK_Source/Games/RWK/Resources
SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy ./kittyengine --oracle \
    --level=../../../../samples/minimal/minimal.kitty \
    --tape=../../../../samples/minimal/minimal.tape.csv \
    --ticks=110 --seed=1 --out=/tmp/obs.csv
```

### Browser (WebAssembly)

```bash
EMSDK_ENV=/path/to/emsdk/emsdk_env.sh ./wasm/build.sh
python3 -m http.server 8000 --directory wasm/page
```

`./wasm/build.sh --relink` links from the existing object cache; `--fresh`
throws that cache away first.

See [Windows-Build-Guide.md](Windows-Build-Guide.md).

## The placeholder pack

A missing asset is not survivable in this engine: the sprite loader reads
metadata straight out of a `.bundle` with no existence check, so an absent
image file was a silent segfault at start-up, and the browser build aborts on a
structurally invalid one. Every file the engine opens therefore has to exist.

`tools/genpack/genpack.py` writes all of them — one atlas and one sprite bundle
per bundle the engine loads, a 5×7 bitmap face for every font, a placeholder for
every sound, and the application icon:

```bash
python3 tools/genpack/genpack.py            # write the pack
python3 tools/genpack/genpack.py --check    # regenerate and diff, write nothing
```

Nothing in it is a copy of anything. The generator does not carry a list of the
original's contents: it **reads each bundle's layout out of the engine's own
source** at generation time (the ordered load calls in each `Bundle_*.cpp`'s
"Bundler Automatic Code" block, and the member types the headers declare), takes
the sound names from the `sounds://` references in the source, and the tile
pitch from `World::mGridSize`. Point it at a different revision of the engine
and the pack follows it. The output is original work, dedicated to the public
domain (CC0).

The generated `.ogg` files are empty. The engine opens each of them, warns, and
runs at full frame rate — measured on the native build and in the browser — and
no encoder ships with this repository, so silence here is a zero-length file
rather than a binary blob nobody can regenerate.

## Playing with your own assets

If you own the original game, set `KITTYENGINE_ASSETS` to a copy of its
`Resources` folder:

```bash
KITTYENGINE_ASSETS=/path/to/Resources ./kittyengine
```

Any file present there wins over the placeholder pack. The substitution is **per
file**, so a partial copy works: whatever your folder does not hold keeps coming
from the pack. Nothing is written into your folder.

This is the pattern Mike Hommel sanctions for his own games' source releases —
ship the code, let the people who already own the game provide the content.

## Tests

Both gates are made to go red before they are trusted green; each one can
demonstrate its own failure:

```bash
python3 scripts/no_originals_guard.py            # no original asset is in this tree
python3 scripts/no_originals_guard.py --self-test
python3 scripts/completability_gate.py           # every demo level is still solvable
python3 scripts/completability_gate.py --self-test
```

**The no-originals guard** holds the md5 of every original asset blob in the
full history of the source mirror, plus the level images of the retail
compilation: 1026 hashes. A hash names a file without carrying any of it, which
is why the list can live in a public repository. The guard walks a tree and
fails on any match — and it takes a path, so it also runs over *built
artifacts*. A web build's `index.data` concatenates its inputs, so it unpacks
that payload using emscripten's own offset table rather than hashing the blob
whole, which would pass while shipping every asset inside it.

**The completability gate** replays each demo level's tape in the engine and
requires the engine's own win flag, no death on the way, a world with a real
size, a win after the first tick and inside the manifest's budget, and an
observation digest matching the recorded one. The size check is not decoration:
an absent or empty level file boots a **0×0 world with the win flag already up
at tick 0**, so a gate that only reads the flag passes hardest exactly when the
levels have gone missing.

## The demo levels

`samples/` holds four levels with the input tapes that solve them and the
digests those runs produce. They come from
[kittygif](https://github.com/PeerInfinity/kittygif), where they are generated
from that project's id table; none of them is original level data.

| sample | grid | wins at tick |
|--------|------|--------------|
| `minimal` | 12×6 | 78 |
| `steps` | 47×12 | 416 |
| `corridor` | 101×12 | 1034 |
| `corridor-rwk` | 231×12 | 2422 |

## Layout

| path | what it is |
|------|------------|
| `RWK_Source/Framework/` | RAPT, the engine's own framework, and the per-OS layers |
| `RWK_Source/Games/RWK/Source/` | the game: world, player, editor, bundles |
| `RWK_Source/Games/RWK/Project/` | the Linux, Windows and CMake project files |
| `RWK_Source/Games/RWK/Resources/` | the generated placeholder pack, and the `.ml` UI markup |
| `wasm/` | the emscripten build, its entry point, and the page shell |
| `samples/` | the four demo levels, their tapes and their expected digests |
| `scripts/` | the no-originals guard and the completability gate |
| `tools/genpack/` | the placeholder pack generator |
