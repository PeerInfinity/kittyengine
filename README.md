# kittyengine

**kittyengine is the C++ engine behind Raptisoft's *Robot Wants* platformer
games, released as code only.** It comes with a build, a generated set of
placeholder graphics, four small demo levels, and tests that check those levels
can still be completed. Several unrelated projects on GitHub are called
"KittyEngine"; this is not one of them.

It contains **no original art, music, fonts or levels**. Everything you see when
you run it is generated by a script in this repository and dedicated to the
public domain. If you own the original game, you can point the engine at your
own copy of its files and play with the real graphics and sound. See
[Playing with your own game files](#playing-with-your-own-game-files).

## This repository

This repository is a **first snapshot, from August 2026**. Development has
continued since then in a separate, private repository, which adds an automated
player, adjustable physics, more test levels and many more checks.

## Where the code came from

This is a new history, not a fork. The starting point is the community's copy
of the original source, [rwkcommunity/rwkgame](https://github.com/rwkcommunity/rwkgame),
at commit `31e8e17`, with every original asset removed before the first commit.
A fork would have carried all 998 original asset files in its history.

Two changes were made before the first commit. The commits that made them are
in a private repository:

- **Audio.** The original used BASS, a commercial audio library. It now uses
  SDL2 and the public-domain `stb_vorbis` decoder.
- **Browser build.** The engine also builds for the web with Emscripten, using
  the Linux graphics code.

## Words used in this repository

| word | meaning |
|------|---------|
| tick | one step of the game simulation |
| tape | a recording of which buttons were held on each tick; replaying a tape replays a run |
| digest | an MD5 checksum of what the engine reported on every tick of a run; if it changes, the run changed |

## Building

### Linux

```bash
sudo apt install cmake clang libsdl2-dev libsdl2-image-dev libglew-dev libcurl4-openssl-dev
cd RWK_Source/Games/RWK/Project/Linux
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

The program is written to `RWK_Source/Games/RWK/Resources/kittyengine`, next to
the files it loads. To run it without a screen, as the tests do, also install
`xvfb libgl1-mesa-dri libglu1-mesa`.

### Browser

```bash
EMSDK_ENV=/path/to/emsdk/emsdk_env.sh ./wasm/build.sh
python3 -m http.server 8000 --directory wasm/page
```

Then open `http://localhost:8000/`. `./wasm/build.sh --relink` reuses the
previous build's compiled files; `--fresh` deletes them first.

### Windows

See [Windows-Build-Guide.md](Windows-Build-Guide.md). No automated test builds
Windows, so that guide is not checked automatically.

## Running it

From `RWK_Source/Games/RWK/Resources`:

```bash
./kittyengine                                   # play the game
SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy ./kittyengine --oracle \
    --level=../../../../samples/minimal/minimal.kitty \
    --tape=../../../../samples/minimal/minimal.tape.csv \
    --ticks=110 --seed=1 --out=/tmp/run.csv    # replay a tape without a screen
```

The replay writes one row per tick describing the robot: its position, speed,
whether it is on the ground or jumping, and whether it has died or won.

## Playing with your own game files

If you own the original game, set `KITTYENGINE_ASSETS` to a copy of its
`Resources` folder:

```bash
KITTYENGINE_ASSETS=/path/to/Resources ./kittyengine
```

Any file in your folder is used instead of the placeholder. This works file by
file, so a partial copy is fine. Nothing is written to your folder.

This follows the approach Mike Hommel takes with his own games' source
releases: publish the code, and let people who own the game supply its content.

## The placeholder graphics

The engine crashes if a file it expects is missing, so every file it opens has
to exist. `tools/genpack/genpack.py` writes all of them: an image and layout
file for every sprite set, a simple 5×7 font, an empty sound file for every
sound, and the icon.

```bash
python3 tools/genpack/genpack.py            # write the files
python3 tools/genpack/genpack.py --check    # check the committed files match
```

The generator copies nothing. It reads what each sprite set needs from the
engine's own source code, so it keeps working if the engine changes. The sound
files are empty on purpose; the engine warns once per file and runs normally.

## Tests

Every push runs two jobs on GitHub Actions, a Linux build and a browser build,
with two main checks. Each check also has a self-test that shows it can fail.

```bash
python3 scripts/no_originals_guard.py              # no original file is here
python3 scripts/no_originals_guard.py --self-test
python3 scripts/completability_gate.py             # every demo level can still be completed
python3 scripts/completability_gate.py --self-test
```

- **No original files.** The guard holds the MD5 checksums of all 1026 original
  asset files and fails if any of them appears. It also checks inside a built
  browser package, which bundles its files together.
- **The levels can still be completed.** The gate replays each demo level's tape
  and requires a win, no death, the recorded digest, and a win inside the
  expected number of ticks. It also checks the level really loaded: a missing
  level starts already won, so a check of the win alone would pass.

## Layout

| path | what it is |
|------|------------|
| `RWK_Source/Framework/` | RAPT, the engine's framework, and the code for each operating system |
| `RWK_Source/Games/RWK/Source/` | the game: world, player, editor, sprite sets |
| `RWK_Source/Games/RWK/Project/` | Linux, Windows and CMake project files |
| `RWK_Source/Games/RWK/Resources/` | the placeholder graphics, and the original menu layout files |
| `samples/` | the four demo levels, their tapes and the expected results |
| `scripts/` | the two checks |
| `tools/` | the placeholder graphics generator, and a level generator |
| `wasm/` | the browser build and its page |
| `docker/`, `run_docker` | Docker files inherited from the community source; not maintained here |
